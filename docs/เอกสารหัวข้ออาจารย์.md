Database : PostgreSQL vs MongoDB

| หัวข้อ                   | PostgreSQL                | MongoDB           |
|------------------------|---------------------------|-------------------|
| ประเภท                 | Relational Database (SQL) | NoSQL Database    |
| รูปแบบข้อมูล              | ตาราง (Table)             | Document (JSON)   |
| Schema                 | กำหนดโครงสร้างชัดเจน        | ยืดหยุ่น             |
| Foreign Key            | รองรับ                     | ไม่รองรับโดยตรง     |
| Transaction            | รองรับเต็มรูปแบบ (ACID)      | รองรับบางส่วน       |
| Query ซับซ้อน            | ดีมาก                      | ปานกลาง           |
| เหมาะกับข้อมูลที่มีความสัมพันธ์ | เหมาะมาก                  | เหมาะปานกลาง      |
| ใช้งานร่วมกับ Django      | ดีมาก                      | ต้องใช้ Library เพิ่ม |
| ใช้งานร่วมกับ FastAPI     | ดีมาก                      | ดี                 |

ตัวอย่างองค์กรที่ใช้ PostgreSQL

Instagram

- ใช้ PostgreSQL ร่วมกับระบบ Backend

- รองรับการจัดการข้อมูลที่มีความสัมพันธ์ซับซ้อน

ข้อดี

- รองรับ Foreign Key และ Relationship

- รองรับ Transaction แบบ ACID

- มีความเสถียรสูง

- รองรับ Query ที่ซับซ้อน

- ทำงานร่วมกับ Django และ FastAPI ได้ดี

- มีเครื่องมือจัดการฐานข้อมูลจำนวนมาก

ข้อจำกัด

- ต้องออกแบบ Schema ล่วงหน้า

- ปรับโครงสร้างข้อมูลได้ยากกว่า MongoDB

- เหมาะกับข้อมูลที่มีโครงสร้างชัดเจนมากกว่า

MongoDB

ตัวอย่างองค์กรที่ใช้ MongoDB

- ใช้ MongoDB สำหรับระบบที่ต้องจัดเก็บข้อมูลหลากหลายรูปแบบ

ข้อดี

- โครงสร้างข้อมูลยืดหยุ่น

- เพิ่ม Field ใหม่ได้ง่าย

- เหมาะกับข้อมูลที่เปลี่ยนแปลงบ่อย

- รองรับการขยายระบบในแนวนอนได้ดี

ข้อจำกัด

- จัดการความสัมพันธ์ระหว่างข้อมูลได้ยากกว่า PostgreSQL

- Query ที่ซับซ้อนทำได้ยากกว่า

- ไม่เหมาะกับระบบที่มี Foreign Key จำนวนมาก

- ต้องดูแล Data Consistency เพิ่มเติม

## Architecture 1: Monolith (Django + PostgreSQL)

### 1. นายปิยะพงษ์

#### Table 1: Unified Users (ตารางผู้ใช้งานรวม)

จัดการข้อมูลนักศึกษาและบุคลากรในตารางเดียว รวมข้อมูลส่วนตัว คณะ และสิทธิ์การใช้งาน

**CRUD:**

- **Create** – เพิ่มข้อมูลผู้ใช้ใหม่

- **Read** – ดูรายละเอียด/ค้นหาข้อมูลผู้ใช้

- **Update** – แก้ไขข้อมูลส่วนตัว/คณะ/สิทธิ์การใช้งาน

- **Delete** – ลบ/ปิดใช้งานบัญชีผู้ใช้

#### Table 2: Bicycle Management (ตารางจัดการจักรยาน)

จัดการข้อมูลจักรยานและสถานะการใช้งาน

**CRUD:**

- **Create** – เพิ่มจักรยานคันใหม่เข้าระบบ

- **Read** – ดูรายการ/สถานะจักรยานทั้งหมด

- **Update** – แก้ไขข้อมูล/สถานะจักรยาน เช่น พร้อมใช้-ไม่พร้อมใช้

- **Delete** – ลบจักรยานออกจากระบบ

#### Table 3: Maintenance (ตารางบำรุงรักษา)

จัดการประวัติการแจ้งซ่อมและบำรุงรักษาจักรยาน

**CRUD:**

- **Create** – เพิ่มบันทึกแจ้งซ่อม/บำรุงรักษา

- **Read** – ดูประวัติการแจ้งซ่อมทั้งหมด

- **Update** – แก้ไขสถานะงานซ่อม เช่น กำลังซ่อม-ซ่อมเสร็จ

- **Delete** – ลบบันทึกการแจ้งซ่อมที่ผิดพลาด

### 2. นายวีรพันธ์

#### Table 1: Staff/Officer Management (ตารางจัดการเจ้าหน้าที่)

จัดการข้อมูลเจ้าหน้าที่ผู้ดูแลระบบ ตำแหน่ง และสิทธิ์การเข้าถึง

**CRUD:**

- **Create** – เพิ่มข้อมูลเจ้าหน้าที่ใหม่เข้าระบบ

- **Read** – ดูรายการ/รายละเอียดเจ้าหน้าที่ทั้งหมด

- **Update** – แก้ไขข้อมูลเจ้าหน้าที่ เช่น เปลี่ยนตำแหน่ง/สิทธิ์การเข้าถึงระบบ

- **Delete** – ลบ/ปลดเจ้าหน้าที่ที่พ้นสภาพออกจากระบบ

#### Table 2: Campus Announcements (ตารางประกาศข่าวสาร)

ระบบจัดการข่าวสารหรือประกาศหน้าแอปเพื่อให้ Admin เพิ่ม/ลบข่าวประชาสัมพันธ์ได้

**CRUD:**

- **Create** – เพิ่มข่าวประชาสัมพันธ์ใหม่

- **Read** – ดูรายการข่าว/ประกาศหน้าแอป

- **Update** – แก้ไขเนื้อหาข่าวที่ประกาศไปแล้ว

- **Delete** – ลบข่าวที่หมดอายุหรือไม่เกี่ยวข้อง

#### Table 3: System Audit Logs (ตารางบันทึกตรวจสอบระบบ)

บันทึกการแก้ไขข้อมูลสำคัญในระบบเพื่อความโปร่งใส

**CRUD:**

- **Create** – เพิ่มบันทึก Log อัตโนมัติเมื่อมีการแก้ไขข้อมูลสำคัญ

- **Read** – ดูประวัติการเปลี่ยนแปลงข้อมูลในระบบ

- **Update** – แก้ไข Log โดย Admin สูงสุดเท่านั้น

- **Delete** – ลบ Log เก่าที่ไม่จำเป็น โดย Admin สูงสุดเท่านั้น

- **Delete –** ลบรายการของหายที่ยกเลิก

### 5. นายชัยอนันต์

#### Table 1: Reservation & Booking (ตารางการจองล่วงหน้า)

ตารางจัดการการจองล่วงหน้า รวม Logic การตรวจสอบความพร้อมใช้งาน (Availability) และการเริ่มยืม (Borrow) ไว้ในตารางนี้

**CRUD:**

- **Create** – เพิ่มการจองจักรยานล่วงหน้า

- **Read** – ดูสถานะการจอง/ความพร้อมใช้งานของจักรยาน

- **Update** – แก้ไขการจอง เช่น เปลี่ยนเวลา/เริ่มยืม

- **Delete** – ลบ/ยกเลิกการจอง

#### Table 2: Group Ride Bookings (ตารางกลุ่มปั่นร่วมกัน) 

ระบบที่ให้นักศึกษาสามารถตั้งกลุ่มปั่นจักรยานไปยังจุดหมายต่างๆ ในมหาวิทยาลัยร่วมกัน เพื่อหาเพื่อนร่วมทางและเพิ่มความปลอดภัยในการเดินทางเป็นกลุ่ม

**CRUD:**

- Create (สร้างกลุ่ม): ผู้ใช้สามารถตั้งกลุ่มปั่นใหม่ ระบุชื่อกลุ่ม จุดหมายปลายทาง เวลานัดหมาย และจำนวนสมาชิกที่ต้องการเปิดรับ

- Read (ค้นหา/ดูกลุ่ม): สมาชิกคนอื่นๆ สามารถเข้ามาดูรายชื่อกลุ่มปั่นรอบตัวที่สถานะยังเป็น Open เพื่อดูรายละเอียดและตัดสินใจเข้าร่วม

- Update (เข้าร่วมกลุ่ม/แก้ไขกลุ่ม)

  - สำหรับผู้ใช้ทั่วไป: กด "เข้าร่วมกลุ่ม" ระบบจะบวกเพิ่มจำนวนในฟิลด์ และเปลี่ยนสถานะเป็น Full หากคนเต็ม

  - สำหรับหัวหน้ากลุ่ม: สามารถเข้าไปแก้ไขเวลานัดหมายหรือจุดหมายปลายทางได้

- Delete (ยกเลิกกลุ่ม/ออกจากกลุ่ม): หัวหน้ากลุ่มสามารถกดยกเลิกกลุ่ม (สถานะเปลี่ยนเป็น Cancelled) หรือสมาชิกขอกดออกจากกลุ่มเพื่อคืนโควตาให้คนอื่นได้

#### Table 3: Support Tickets (ตารางรับแจ้งปัญหา)

ระบบรับแจ้งปัญหาการใช้งาน เช่น แอปค้าง หรือพบปัญหาที่จุดจอด เพื่อให้เจ้าหน้าที่ตรวจสอบและแก้ไข

**CRUD:**

- **Create** – เพิ่มคำร้องแจ้งปัญหาการใช้งาน

- **Read** – ดูรายการคำร้องที่แจ้งไว้/สถานะการแก้ไข

- **Update** – แก้ไขสถานะคำร้อง เช่น กำลังตรวจสอบ-แก้ไขแล้ว

- **Delete** – ลบคำร้องที่ปิดเคสแล้ว
